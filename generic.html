Generic Backups

The generic subcommand runs standard restic operations against any configured backup. Backup sources may be files or directories anywhere on the machine.

Set RESTIC_BACKUPS_CONFIG first, or pass --config before generic. See the Quick Start for a complete first backup.

Commands

Group Command Purpose Remote storage
Repository generic repository list Show configured repositories No
Repository generic repository init [REPOSITORY] [--all] [--dry-run] Initialize new repositories Yes
Repository generic repository prime-cache [REPOSITORY] Cache and validate repository metadata Yes
Repository generic repository destroy [REPOSITORY] [--dry-run] Permanently erase one repository Yes
Backup generic backup list Show configured backup jobs No
Backup generic backup run [JOB_ID] [--dry-run] Create a snapshot from configured paths Yes
Backup generic backup data-dir [JOB_ID] Print the managed private-data directory No
Snapshot generic snapshot list [JOB_ID] List snapshots for a configured backup Yes
Snapshot generic snapshot forget [JOB_ID] [--dry-run] Forget one tagged snapshot and prune Yes
Restic generic restic run --backup JOB_ID ... Pass trailing arguments directly to restic Depends on restic command

Commands that accept [JOB_ID] prompt when it is omitted in an interactive terminal. Non-interactive callers must provide the job ID.

Running restic-backups generic without a subcommand in an interactive terminal opens a section menu for repositories, backups, snapshots, and advanced restic commands. Every section and command has a short description and is selectable with the arrow keys. Explicit subcommands remain available for scripts and scheduled jobs. Advanced restic reads the installed restic version’s command list and descriptions. After selection it shows the command’s restic usage, prompts for arguments, and prints the complete copyable uv run restic-backups command. Choose Run, Print only, or Cancel. Choose Help at any level to see help for the current section or selected restic command and return to the same menu. Showing help does not load the configuration, select a backup, or contact the repository. Back returns one level without restarting the menu tree. Entering --help or -h in the argument prompt has the same local-help behavior.

Dry runs

The interactive menu shows a Dry run checkbox for repository initialization, repository destruction, backup creation, and snapshot forgetting. Press Space to toggle it, then Enter to continue. A dry run performs any reads needed to report what would happen but does not initialize or destroy a repository, upload backup data, create a snapshot, forget a snapshot, or prune data.

Advanced restic commands show the same checkbox when the installed restic version advertises a native --dry-run flag for the selected command. Commands without that flag do not show the checkbox; use Print only to inspect their complete command without running it.

Explicit commands can pass --dry-run directly to the managed write commands:

uv run restic-backups generic repository init personal --dry-run
uv run restic-backups generic backup run documents --dry-run
uv run restic-backups generic snapshot forget documents --dry-run
uv run restic-backups generic repository destroy personal --dry-run

generic repository list shows every store, even when no configured backup references it. generic backup list shows the configured backup jobs.

generic repository init prompts for one repository, with All repositories as the first option. Scripts must pass a repository ID or --all. Disabled or already initialized repositories are reported and skipped.

generic repository prime-cache runs restic check --with-cache for one repository. It downloads repository indexes, snapshots, and tree metadata into the configured cache while also validating repository structure. It does not download backed-up file contents; restic only does that when --read-data is requested explicitly.

Create a snapshot

Configure the local source paths once, then select the backup by its ID:

backups:
  - job-id: documents
    restic-store-id: personal-store
    paths:
      - ~/Documents
      - ~/Desktop
uv run restic-backups generic backup run documents

The command expands ~, passes the paths to restic backup, and applies the job ID as the restic tag unless tag is explicitly configured. Every run creates a snapshot of the complete source state while restic uploads only new or changed file data.

List snapshots

List snapshots with the configured backup tag:

uv run restic-backups generic snapshot list documents

The table shows each snapshot’s short restic ID, timestamp, host, paths, and tags.

Forget one snapshot

uv run restic-backups generic snapshot forget

Forgetting is interactive-only. Select a configured backup, select one snapshot with its configured restic tag, and confirm. The CLI runs restic forget --prune, so the snapshot and data no longer referenced by any other snapshot are permanently removed. The configured backup and repository remain available.

When several configured backups share a repository, their restic tags keep their snapshots distinct in the picker.

Permanently destroy a repository

uv run restic-backups generic repository destroy

Destruction is interactive-only. The CLI shows the full S3 target, asks for a yes/no confirmation, then requires the exact repository ID. It deletes every object, object version, and delete marker below the configured bucket and key_prefix. It does not delete the bucket or change the YAML configuration.

The provider credentials need permission to list objects and versions and to delete objects and versions. An empty key_prefix is always rejected to prevent accidental bucket deletion.

Repository deletion is irreversible. Snapshots, indexes, repository keys, and encrypted data are all erased. The configured restic password cannot recover them.

Common operations

# Inspect and check the repository
uv run restic-backups generic snapshot list documents
uv run restic-backups generic restic run --backup documents check
uv run restic-backups generic restic run --backup documents list snapshots

# Restore a snapshot
uv run restic-backups generic restic run --backup documents \
  restore <snapshot-id> --target /tmp/documents-restore

Arguments after the backup selection are passed to restic unchanged. The CLI exports the selected repository and credentials only to the child process and does not print them. For the backup command, it also adds the configured restic tag automatically; additional --tag arguments remain supported.

Managed data directory

uv run restic-backups generic backup data-dir documents

The result follows data/<store-id>/<bucket>/<key-prefix>/<job-id>/ beside the selected config file. It is for private generated metadata; generic backup sources do not need to live there.

Cold S3 storage

GLACIER_IR supports immediate access. GLACIER and DEEP_ARCHIVE permit uploads, but retrieval-related commands require the configured restore policy and an explicit acknowledgement:

ALLOW_ARCHIVE_RETRIEVAL=1 uv run restic-backups generic restic run \
  --backup archive restore latest --target /tmp/archive-restore

Other restic commands are rejected for cold repositories when the CLI cannot determine that they are safe. See Configuration for the archive policy fields.
